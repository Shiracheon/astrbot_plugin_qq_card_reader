# QQ 卡片阅读器

为 NapCat / OneBot v11 接入的 AstrBot，将 QQ JSON 消息转换为模型可以阅读的文字。网易云音乐、QQ 音乐、B 站和小黑盒使用专用摘要，其他 JSON 默认提取标题、作者、描述、正文节选、来源和分享链接。

版本：`v0.5.0`。按 AstrBot `v4.28.2` 的接口实现，无额外 Python 依赖。

作者：Shiracheon。开源许可证：MIT，完整文本见 [LICENSE](LICENSE)。

## 安装

1. 在 AstrBot 管理面板打开 **插件**。
2. 找到 **安装插件 / 从文件安装 / 上传插件** 一类入口，上传 `astrbot_plugin_qq_card_reader-v0.5.0.zip`。已有旧版时覆盖更新。
3. 安装成功后确认 **QQ卡片阅读器** 已启用；当前配置文件的插件集合也需要包含该插件。若插件集合是 `*`，无需另外添加。
4. 插件默认开启四类平台解析、通用 JSON 转文字及短期缓存。升级后确认“将其他JSON消息的字段转换为普通文字”和“通用JSON仅提取主要信息”均已开启。

若面板没有文件上传入口，把本目录复制到服务器实际的 AstrBot 数据目录中：

```text
data/
  plugins/
    astrbot_plugin_qq_card_reader/
      main.py
      __init__.py
      card_parser.py
      card_cache.py
      metadata.yaml
      _conf_schema.json
      README.md
```

复制后重启 AstrBot 或通过面板重载插件。Docker 部署时使用你已经挂载到容器 `/AstrBot/data` 的宿主机目录；不要把插件放到 NapCat 的插件目录。

## 使用

### 当前消息

私聊直接发送一张网易云、QQ 音乐、B 站或小黑盒卡片，插件会把标题、描述、链接和有效的封面地址补充到本条消息文字中。是否调用模型仍由 AstrBot 的私聊唤醒设置决定。

网易云卡片转换示例：

```text
[网易云音乐分享卡片]
标题：ライアーメイデン (feat. りぃふ) (说谎的少女)
歌手/描述：ヤバス/りぃふ
链接：https://music.163.com/song?id=2063845804
```

网易云兼容 `meta.news` 普通分享卡片和 `meta.music` 原生音乐卡片；两种格式均从 `jumpUrl` 提取分享链接，`musicUrl` 不作为分享链接。B 站小程序卡片使用 `meta.detail_1.desc` 作为分享标题，避免把“哔哩哔哩”这个应用名当成视频标题。普通分享卡片使用 `meta.news`。

QQ 音乐支持日志中的 `com.tencent.tuwen.lua` / `meta.news` 格式，也可读取相同字段的 `meta.music` 卡片。通过 `y.qq.com` 及其子域名、“QQ音乐”标签或应用 ID `100497308` 识别；歌手/描述来自 `desc`，分享链接来自 `jumpUrl`。链接保留 `songmid`、`songid`、短链标识及未知路由参数，移除 `hosteuin`、`ADTAG`、`appshare` 等分享者或来源参数，不自动展开短链接。

QQ 音乐转换示例（标题按实际卡片提供的文本保留，不补全被截断的部分）：

```text
[QQ音乐分享卡片]
标题：One Last Kiss (最后一吻)（《新世纪福音...
歌手/描述：宇多田光 (宇多田ヒカル)
链接：https://i.y.qq.com/v8/playsong.html?songmid=003Rxsvb1Wvl5U&type=0
```

小黑盒支持日志中的 `com.tencent.tuwen.lua` / `meta.news` 分享格式，通过 `xiaoheihe.cn` 域名、“小黑盒”标签或应用 ID `1105910806` 识别。分享链接保留 `link_id`、`h_ch` 等定位和路由字段，移除 `h_session_id` 与 `h_src`；不将分享者的会话和来源字段补充给模型。

小黑盒卡片转换示例（封面地址另按卡片字段补充）：

```text
[小黑盒分享卡片]
标题：[碧蓝档案] 甜品部 活动新立绘，甜品部还是美味～
描述：下载小黑盒查看更多精彩内容
链接：https://api.xiaoheihe.cn/v3/bbs/app/api/web/share?h_ch=link&link_id=6659729b30dc&new_post_share_style_v2=0
```

“下载小黑盒查看更多精彩内容”是卡片描述，不是帖子正文。插件不打开网页或识别封面画面，模型应根据实际标题回答。

### 引用消息

引用卡片并问“这首歌叫什么”“这个视频是什么”或“这是什么”。四类卡片和通用 JSON 使用相同的引用处理流程。群聊通常还需要 @ bot 或使用原有唤醒词。

处理顺序为：引用消息链 → 相同聊天中该消息 ID 的缓存 → 引用内容缺失或只保留分享预览文字时调用 NapCat `get_msg`。获取失败或超过 3 秒时保留原消息，继续正常处理。不会用附近的另一张卡片代替明确引用的消息。解析成功时同步补充引用消息的 `chain`、`message_str` 和兼容字段 `text`，使 AstrBot 单独收集的引用内容也有文字。

### 其他 JSON 消息

未被四类平台解析器识别的 JSON 消息，默认通过本地字段名规则提取主要信息。例如其他应用分享的卡片可转换为：

```text
[JSON消息转文字]
标题：普通分享标题
字段内容：
作者：发布者名称
描述：其他应用提供的文字
链接：https://example.com/article?id=42
```

转换在服务器上完成，不额外调用模型进行摘要。根据 `title` / `headline`、`author` / `artist`、`desc` / `summary`、`content` / `text`、`jumpUrl` / `share_url` 等字段选择内容，兼容大小写、下划线及部分中文字段名。嵌套对象、数组、字符串形式的内嵌 JSON 也会检查；作者对象中的 `name` / `nickname` 可提取为作者，应用对象中的 `name` 可提取为来源。优先使用实际标题，缺少标题时再使用 QQ 的 `prompt` 预览。

主要信息模式跳过配置、时间戳、账号 ID、统计值、封面和图标地址、播放地址等；不会根据字段值猜测未知字段的含义，也不会把分享者昵称直接当成作品作者。没有识别到有用字段时只提供说明，数字、布尔值、空值等不会作为作品内容展示。保留原始 JSON 组件，并向标准文字字段及 `Plain` 消息段补充转换结果。

来源最多 60 字符，标题最多 160 字符，作者最多 120 字符，描述最多 300 字符，正文节选最多 600 字符。去重后每类最多选择 3 个文本，再合并并按上述长度缩短；分享链接保留一个完整地址，超过 600 字符时省略并说明有信息未展示。正文节选只是消息中正文的片段，不是模型生成的摘要。多条内容、未知字段名或超限字段可能被省略。

若某种新卡片没有被正确提取，可关闭“通用JSON仅提取主要信息”，恢复 v0.4.0 的字段路径展开模式。两种模式均支持当前消息、引用和缓存；切换后重载插件并重新发送卡片，以刷新缓存内容。

默认每个通用 JSON 的字段文字上限为 3000 字符，最多检查 6 层、遍历 200 个节点；主要信息模式通常不会用满字符上限，标题和外围说明另计。完整展开模式的单个普通文字字段最多 600 字符。超限时显示说明。超过 131072 字符的 JSON 字符串，或格式异常的数据，仅提供状态说明，不展开原始内容。

根据字段名跳过 `token`、`secret`、`password`、`cookie`、`authorization`、`session_id`、`api_key` 等值，完整展开模式以“已隐藏”替代，并移除 HTTP(S) 链接中同类查询参数。此规则不保证识别普通正文中夹杂的敏感信息。字段里的指令仍属于用户消息内容。四类已知平台沿用专用摘要和各自开关；关闭某个平台后，不会绕过开关使用通用转换。

该功能读取 JSON 已经提供的内容；只有链接、标题或封面地址时，不会自动得到网页全文或图片画面。

### 短期缓存

先发送卡片，再在 5 分钟内问：

- “刚才那首歌叫什么？”
- “刚才 QQ 音乐分享的那首歌叫什么？”
- “刚才那个视频是什么？”
- “上面分享的卡片是什么？”
- “刚才那篇帖子是什么？”
- “刚才那个小黑盒分享是什么？”
- “刚才那条消息是什么？”
- “刚才那条 JSON 消息是什么？”（仅筛选通用 JSON 缓存）

群聊里，即使发卡片时未 @ bot，也会记录卡片；之后 @ bot 提问即可。缓存按平台实例、机器人账号、群聊或私聊隔离。同一群的成员可以问其他成员分享的卡片；即使 AstrBot 开启群成员独立 LLM 会话，这份群内卡片缓存仍共享。不同群、不同私聊对象和不同机器人账号之间不共享。

插件只在有卡片指代或明确提及缓存中标题时补充历史卡片，不会把卡片加进每轮闲聊。多张卡片同时符合时列出候选的标题、发送者、消息 ID 和收到时间，提示模型确认指代。到期后无法继续自动关联，仍可尝试直接引用原消息。

“刚才那首歌”等没有指定平台的音乐提问同时匹配网易云和 QQ 音乐卡片，不将视频或帖子当作歌曲。明确提到“QQ音乐”或“网易云”时只筛选对应平台；多首歌曲符合时仍列出候选，不凭空选定一首。

也支持卡片发出后默认 60 秒内的“识别一下”“这个”“看看这个”“这是什么”等简短追问。期间若用户又发送新的图片、视频、音频、文件或合并转发，这类简短追问不会自动关联到更早的卡片；明确提到“刚才那首歌”“刚才那篇帖子”等仍使用完整的 5 分钟缓存。提到“小黑盒”时优先筛选小黑盒卡片，即使问题同时出现“视频”等词；多张卡片同时符合时仍保留候选，不凭空选定一张。

缓存仅在内存中保留；插件重载和 AstrBot 重启后清空。到期记录在下一次缓存访问时清理，聊天数和每个聊天消息数另有上限。

## 配置

| 配置 | 默认值 | 说明 |
|---|---|---|
| `enable_netease` | `true` | 解析网易云音乐卡片 |
| `enable_qqmusic` | `true` | 解析 QQ 音乐卡片 |
| `enable_bilibili` | `true` | 解析 B 站卡片 |
| `enable_heybox` | `true` | 解析小黑盒卡片 |
| `enable_generic_json` | `true` | 将其他 JSON 的字段转为普通文字 |
| `generic_json_extract_only` | `true` | 仅提取主要信息；关闭则恢复字段路径展开 |
| `generic_json_max_chars` | `3000` | 通用 JSON 字段文字上限，500–12000 字符 |
| `generic_json_max_depth` | `6` | 通用 JSON 展开层级，1–10 |
| `enable_recent_context` | `true` | 后续提问使用短期缓存 |
| `cache_ttl_seconds` | `300` | 缓存保留 30–3600 秒 |
| `short_followup_window_seconds` | `60` | 简短追问的关联窗口，1 秒至缓存时长 |
| `cache_messages_per_session` | `10` | 每个聊天保留 1–50 条卡片消息 |
| `cache_max_sessions` | `200` | 最多保留 1–1000 个聊天 |
| `max_cards_per_message` | `3` | 每条消息解析 1–10 张卡片 |
| `max_recent_candidates` | `3` | 显示给模型的候选数量，1–10 |
| `fetch_missing_reply` | `true` | 引用内容缺失时通过 NapCat 获取原消息 |

修改配置后建议重载插件，使缓存参数重新生效。

## 和其他插件配合

消息监听器以 `priority=10000` 注册，在默认优先级的消息采集插件之前补充文字，并同步更新 `event.message_str`、`event.message_obj.message_str` 和 `Plain` 消息段。原始 JSON 卡片保留。模型请求钩子只在请求缺少这份文字时再次补充，避免重复。

因此能给使用这些标准字段的 `self_learning` 等插件提供文字输入。若其他插件使用自定义采集路径、更高优先级、或在更晚的钩子里覆盖了请求，需要通过实际日志确认顺序。

## 读取范围

- 读取 JSON 消息本身已经提供的字段，不访问分享网页，不下载封面、歌曲或视频。
- 不另外获取歌词、字幕、视频或帖子正文；JSON 本身有正文字段时可以提取节选，否则模型仅凭标题或描述无法可靠总结完整内容。
- 通用转换仅处理 JSON 消息组件，不解析裸链接、XML 卡片或合并转发内部卡片。
- B 站短链接保留短链接形式；B 站动态、直播和个人空间只标为“B站分享卡片”，不假定一定是视频。
- 群聊是否回答沿用 AstrBot 的 @、唤醒词等规则；本插件不强制唤醒或主动发送解析结果。

## 服务器验收

1. 私聊发送网易云音乐卡片，确认 bot 能识别歌名与描述。
2. 私聊发送 B 站小程序卡片，确认 bot 能识别实际分享标题。
3. 在群里先发卡片，再引用卡片并 @ bot 提问。
4. 不引用卡片，在 5 分钟内 @ bot 问“刚才那首歌叫什么”。
5. 连续发两张歌曲卡片再问“刚才那首歌”，确认回答不凭空确定指代。
6. 在另一个群或私聊里问同样的问题，确认没有借用上一聊天的缓存。
7. 等缓存过期，确认无引用的提问不再得到插件的旧缓存补充。
8. 私聊发送截图中的小黑盒卡片，确认 bot 能识别“碧蓝档案”“甜品部”等标题信息；再引用卡片问“这是什么”。
9. 发小黑盒卡片后，60 秒内不引用问“识别一下”；5 分钟内问“刚才那篇帖子是什么”，确认缓存匹配正常。
10. 关闭小黑盒解析后重载插件，确认小黑盒不再补充文字，网易云和 B 站仍按各自开关工作。
11. 私聊发送截图中的 QQ 音乐卡片，确认 bot 能读到 `One Last Kiss` 与 `宇多田光`；引用问“这是什么”，再不引用问“刚才那首歌叫什么”。
12. 先后发网易云与 QQ 音乐卡片，问“刚才那首歌”时确认保留候选；问“QQ音乐那首歌”时确认只匹配 QQ 音乐。
13. 关闭 QQ 音乐解析后重载插件，确认该平台不再补充文字，其他平台仍按各自开关工作。
14. 发送其他应用的 JSON 分享卡片，确认出现“JSON消息转文字”及标题、描述、链接等主要信息；引用提问，再测试“识别一下”和“刚才那条消息是什么”。
15. 关闭通用 JSON 转文字并重载插件，确认未知 JSON 不再展开，开启的四类平台仍有专用摘要。
16. 关闭“通用JSON仅提取主要信息”并重载插件，重新发送未知 JSON，确认恢复字段路径展开。

开启 DEBUG 日志后可看到：

```text
[QQ读卡] v0.5.0 已加载，缓存=300秒，简短追问窗口=60秒
[QQ读卡] 消息监听：组件=Json，支持的卡片=1，引用=0，原文字长度=0，网易云=True，QQ音乐=True，B站=True，小黑盒=True，通用JSON=True
[QQ读卡] 已补充文字：当前卡片=1，引用=0，缓存=False
[QQ读卡] 模型请求：已包含卡片文字
```

在正常允许模型回答的私聊中，已成功解析的单独卡片应不再因“empty message”跳过模型。若仍不回答，检查模型是否启用、私聊唤醒规则和其他插件是否阻止请求。安装前发送的卡片不会自动进入缓存，需要重新发送或引用。

## v0.5.0 更新

- 通用 JSON 默认只提取标题、作者、描述、正文节选、来源及有效分享链接，减少无关字段进入模型上下文。
- 本地筛选及去重，不额外调用模型；支持嵌套作者、内嵌 JSON、常见字段别名及缺少标题时的预览回退。
